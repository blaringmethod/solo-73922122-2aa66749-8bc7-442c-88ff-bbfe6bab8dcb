# 陶瓷质检迁库 · 炉次试片尺寸超差核查

迁库时尺寸只保留了**取整后的新表读数**。本系统按炉次开单，结合公差、新表分辨率、
零点偏差范围与配对旧值/纸档真值，判定一炉试片是否需要回查纸档，并给出
**超差件数的最小值与最大值**（各附一个能达到该件数的偏差），支持纸档补录/更正与
冲突管理。技术栈：Flask + SQLite（标准库 sqlite3），Docker Compose 一键启动。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000
```

不用 Docker 也可以本地跑：

```bash
pip install -r requirements.txt
DATABASE=./data/app.db python -m app.main     # 默认 5000 端口，PORT 环境变量可改
```

## 核心语义（全部 Decimal 精确小数，区间均含端点）

- 开单时在对照页选择**炉次列、炉次值与尺寸列**（另选配对列，如试片编号），
  按同一份在供对照开单，**固定该炉全部新表读数及配对旧值**（快照进单据，
  之后的重传/重开不影响已开单据）。
- 填写**公差上下限 `[L, U]`、新表分辨率 `s`、零点偏差范围 `[zlo, zhi]`**。
- 全炉共用一个偏差 `d`（`d ∈ [zlo, zhi]`）；每条新读数 `r` 减去偏差后，
  上下各半个分辨率 `h = s/2` 是真值范围：`[r-d-h, r-d+h]`。
- 真值取证据：**有纸档以纸档值为真值，否则用配对旧值；两者皆无即为自由件，
  可在自身范围内任取真值**。
- 固定件（有证据值 `t`）要求 `t ∈ [r-d-h, r-d+h]`，等价于
  `d ∈ [r-t-h, r-t+h]`。所有固定件约束与零点区间的**交集**即共同可行偏差集；
  交集为空则**冲突**。
- 超差：真值不在公差 `[L, U]` 内（贴边合格）。固定件结论与 `d` 无关；
  自由件按其范围能否触及公差区，分为"可合格"与"恒超差"。
- 输出可行 `d` 区间上**超差件数的最小值、最大值，及各自对应的一个偏差**。
- **无共同可行偏差时仍收录纸档**，撤下旧件数区间并把单据标记为冲突、
  列出冲突约束；更正纸档后自动恢复核算。

### 为什么不用枚举（性能约束）

支持单炉 2 万行，且**不枚举偏差刻度、不对每个边界重扫全炉**：

- 固定件只做一次区间交集 O(n)；
- 自由件的"可合格偏差区间"用一次**区间覆盖扫掠** O(n log n) 求出覆盖数的
  最大/最小值，超差件数 = 恒定超差底数 +（可合格自由件数 − 覆盖数）；
- 纸档补录后整单按上述流程重算一次，仍是 O(n log n)。

## 演示流程（开单 → 补录 → 冲突 → 并发）

样例数据在 `sample_data/`（旧表 170 行、新表 200 行；`python3 scripts/make_sample_data.py` 可重生成）。
页面操作，或跑自动演示 `python3 scripts/demo.py http://localhost:8000`：

1. **上传** `old_system.csv`（旧系统）与 `new_system.csv`（新系统），表头须一致，每份 ≤ 20000 行。
2. **选列**：炉次列=`炉次`、尺寸列=`尺寸`、配对列=`试片编号`。
3. **F01 开单**（60 行全配对，3 条真值在公差外）：超差件数恒为 **3 件**，
   共同可行偏差收缩到唯一点 `-0.030`。
4. **F02 开单**（50 固定 + 10 自由）：超差件数 **0 ~ 10 件**，两个极值各附偏差。
5. **F03 开单**：全部合格，**0 件**。
6. **F04 开单**（20 行无任何证据，全自由件）：**0 ~ 20 件**。
7. **凭单号打开 F04，按新表行号补录纸档**（如 181 行 = 10.02）：纸档与核查结论
   **同一事务**生效，自由件转固定件并立即重算。
8. **补录冲突纸档**（182 行 = 5.00）：纸档仍收录，单据置 `conflict`、撤下件数区间；
   再**更正**为 10.03 即恢复可行并重新给出区间。
9. **并发补录不同行**：多个请求同时补不同新表行号，借助 `BEGIN IMMEDIATE`
   串行写事务，各行纸档均保留，按合并后的证据核算。

## JSON API（网页表单同一套逻辑）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/upload` | multipart 上传 `file_a`（旧）、`file_b`（新） |
| POST | `/api/columns` | `{"furnace_col","size_col","pair_col"}`（pair_col 可空） |
| GET | `/api/furnaces` | 新表全部炉次值及行数 |
| POST | `/api/orders` | `{"furnace","tol_lo","tol_hi","resolution","zero_lo","zero_hi"}` 开单并核算 |
| GET | `/api/orders` | 单据列表（含最新结论） |
| GET | `/api/orders/<id>` | 单据详情（逐行证据 + 结论 + 冲突约束） |
| POST | `/api/orders/<id>/paper` | `{"new_row_no","paper_value"}` 补录/更正纸档并重算 |
| GET | `/api/paper` | 纸档补录台账 |
| GET | `/api/state` | 会话全量状态 |

## 自测

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q        # 24 个用例
python scripts/demo.py            # 端到端演示（需服务已启动）
```

覆盖：

- **引擎手算用例**：固定件可行区间与固定超差、自由件扫掠 min/max、
  恒超差自由件、冲突（无共同可行偏差）、区间含端点、Decimal 无浮点误差；
- **服务层**：上传校验（表头不一致 / 超 2 万行 / 列数不符 / 尺寸非数值）、
  列选择校验、开单快照、未知炉次 404、参数校验；
- **纸档**：补录重算、更正引发冲突与恢复、冲突仍收录纸档并撤下区间、
  非本炉行收录但不影响本单、未知单据 404、行号越界 400；
- **事务**：模拟重算异常 → 纸档与结论整体回滚、原状保留；
- **并发**：4 线程补录 4 个不同行全部保留；
- **性能**：2 万行全固定、2 万行全自由扫掠。

实测（本机）：2 万行上传约 0.9s、开单+核算约 1.1s（全自由扫掠约 0.94s）、
单次纸档补录+整单重算约 0.7s；复杂度 O(n log n)，与偏差刻度数量无关。

## 已知限制 / 未完成

- 单会话：同时只维护一份在供对照，重新上传即重置全部单据与纸档（无多项目隔离）。
- 配对按单列等值（同值取首条旧表行），空配对值不参与；未支持多列复合配对。
- 未做登录鉴权与操作审计；CSV 解析假设逗号分隔、首行表头
  （UTF-8/GB18030 自动识别，单元格去首尾空白），尺寸列须为十进制小数。
- 本仓库环境无 Docker 守护进程，`docker compose up` 未实际构建；
  但 Dockerfile 的启动命令（gunicorn + `app.main:create_app()`）
  已在本机用同一命令实测通过，演示脚本对该服务全部断言通过。
